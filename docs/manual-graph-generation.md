# 按需生成知识图谱

## 行为调整

- 审查结束后直接执行结果后处理、保存报告并标记完成，不再自动运行全量 supplemental 上下文生成。
- 审查过程中用于补齐定义、跨文件理解的 RAG 路径保留，不因这次显示层调整而关闭；它可能已经产生可复用索引。
- 后台管理 → RAG 图谱 → 选择已完成或失败的审查任务 → 点击“生成图谱”，才会提交独立的 Celery 图谱任务。
- 打开页面、选择任务、刷新图谱和轮询状态均只读，不创建索引、不重新执行全量检索。
- 任务状态为 idle / queued / running / completed / failed，独立于审查状态、进度、耗时和报告。失败可重试；排队、生成中和已完成时重复提交不会重复生成。
- 图谱任务复用有效索引及解析、嵌入缓存，生成关系和可观测性快照；不覆盖模型审查时保存的证据。
- 报告页移除“审查补充信息”卡片及对应 evidence 请求，其他报告结果保持不变。

## 更新部署

本次不仅是前端修改，需要同步更新 API、worker 和前端。

1. 在维护窗口等待已有审查完成，停止旧 API/worker 接收新任务并备份数据库。不要中途杀掉正在执行的审查。
2. 在项目后端环境、已配置数据库连接的情况下执行 `alembic upgrade head`。
3. 新增迁移为 `0016_manual_graph_build`，只给 `review_tasks` 添加三个图谱状态字段。历史记录默认 idle，不删除报告、索引、模型或上传文件。
4. 启动新 API 和 worker，发布新前端。worker 的 Celery include 已注册 `app.tasks.code_index`，沿用已有 broker/队列配置，无需增加 GPU 服务。
5. 查看旧报告，确认不请求 evidence；打开图谱页面不应产生构建任务。点击“生成图谱”应立即返回排队状态，后台完成后页面自动加载结果。

## 接口

- `GET /api/code-index/{task_id}/build`：只读状态、已有 project_id 和失败说明。
- `POST /api/code-index/{task_id}/build`：鉴权后异步提交，返回 HTTP 202。审查仍在排队或执行时返回 409，消息队列提交失败返回 503。
- `GET /api/code-index/{task_id}/observability`：只读取已持久化快照，不再隐式建索引或调用嵌入模型。旧索引没有诊断快照时，图结构仍可读取，诊断统计需手动生成后才完整。

原 build 接口的同步返回结构已改为异步状态结构，外部脚本如调用该接口也需相应更新。

## 运行注意

- 当前图谱任务沿用已有 worker 队列。其他任务忙时会排队；关闭页面不会取消后台生成。
- worker 异常退出后的消息重投递可继续同一构建；同一构建在支持行锁的生产数据库中串行处理。
- 若消息队列数据丢失，排队状态不会凭空执行。应检查 broker/worker 并由管理员核实后恢复，不能仅凭耗时判断任务已失败。
- 本次移除的是审查末尾额外的全量整理，并非禁用审查所需的语法解析、索引和 RAG。实际节省时长需要在目标环境以相同输入测量。
- 旧的 `RAG_SUPPLEMENTAL_PERSIST_ENABLED` 配置不再控制审查结尾行为；无论其值为何，都不会自动执行结尾图谱任务。
