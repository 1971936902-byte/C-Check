# DVCP 提示词优化测试记录

本文记录 `hardik05/Damn_Vulnerable_C_Program` 漏洞样例库上的审查策略调试过程和最终落地结论。

## 1. 测试目标

DVCP 样例在单个 `ProcessImage` 函数中密集放置多类 C 语言漏洞，包括：

- 整数溢出和整数下溢
- 堆缓冲区溢出
- 双重释放
- Use-after-free
- 除零
- 栈/堆越界读写
- 指针覆盖导致内存泄漏
- 无限递归和循环分配导致资源耗尽

这类样例适合验证审查系统的“漏洞类型覆盖率”，但和真实项目中的低噪声审查目标不同。测试重点是判断低召回是否来自模型能力不足，还是来自提示词和输出策略。

## 2. 对比方案

| 方案 | 说明 |
| --- | --- |
| 单轮 Top-3 | 原始策略，每次最多返回 3 条 findings。 |
| 单轮放开 Top-3 | 不限制 findings 数量，但不改变审查思路。 |
| 四轮深度审查 | 越界/资源泄漏/生命周期/资源耗尽分别审查。 |
| 单轮覆盖式提示词 | 一次调用内要求模型按漏洞清单逐类扫描；测试阶段最多返回 12 条高价值 findings。 |

## 3. 测试结果

| 指标 | 单轮 Top-3 | 单轮放开 Top-3 | 单轮覆盖式提示词 | 四轮深度审查 |
| --- | ---: | ---: | ---: | ---: |
| 总召回率 | 33.33% | 55.56% | 92.59% | 100% |
| 平均已知精确率 | 88.89% | 91.67% | 87.27% | 85.82% |
| 总 findings | 8 | 14 | 41 | 101 |
| 平均耗时 | 13.48s | 26.67s | 28.64s | 117.81s |
| 解析失败 | 0 | 0 | 0 | 0 |

单轮覆盖式提示词分用例结果：

| 用例 | 命中金标 | 召回率 | findings | 耗时 |
| --- | ---: | ---: | ---: | ---: |
| `dvcp.c` | 8/9 | 88.89% | 15 | 28.44s |

## 4. 关键结论

1. 低召回不是模型完全不能发现漏洞，而是单轮综合审查时模型容易优先输出最显眼的少数问题。
2. 仅放开 findings 数量能提升召回，但仍会漏掉越界读写、资源泄漏和资源耗尽等问题。
3. 四轮深度审查可以达到最高召回，但耗时和报告噪声明显增加，不适合作为默认策略。
4. 单轮覆盖式提示词在召回率、精确率、耗时之间取得了较好平衡，适合作为默认审查策略升级。

## 5. 最终落地策略

默认审查采用单轮覆盖式提示词：

- 测试阶段单次最多返回 12 条高价值 findings；正式落地后为了提升结构化输出稳定性，默认单批次调整为最多 5 条高价值 findings。
- 要求模型在内部按以下顺序扫描：
  1. 整数溢出、整数下溢、截断、除零和不安全长度计算。
  2. 拷贝边界、固定数组/堆数组越界读写、`malloc(n)` 后访问 `[n]`。
  3. `malloc/free` 生命周期问题：双重释放、UAF、悬空指针。
  4. 资源泄漏：指针被 `0` / `NULL` 覆盖前未释放，句柄未关闭。
  5. 资源耗尽：无限递归、大栈帧递归、无界分配循环。
- 同一函数中的不同漏洞类型分别报告。
- 不合并 double free 和 use-after-free。
- 不合并越界读和越界写。
- 去重精确重复项，但保留同一根因造成的不同后果。

正式落地时将输出上限收敛到 5 条，以优先保证真实项目中的结构化稳定性；四轮深度审查暂时不接入默认链路。

## 6. 暂缓合入的方案

四轮深度审查暂时保留为未来的“深度模式”：

- 适合发布前安全专项、基准测试、核心模块深度分析。
- 不建议作为默认审查，因为平均耗时约为默认单轮的 8 到 9 倍。
- 后续若落地，应先用静态规则/RAG 预筛候选点，再对小上下文做专项复审，并配套去重归并。

## 7. 后续优化建议

- 增加规则预筛：`malloc(n)` 后访问 `[n]`、`ptr = NULL` 前未释放、free 后读写、自递归等。
- 增加报告归并：同文件近邻行、同漏洞类型、同根因合并展示。
- 将深度模式做成用户可选项，而不是默认策略。
- 评估集要同时保留“真实项目低噪声集”和“DVCP 高密度漏洞集”，避免单一指标误导产品策略。
